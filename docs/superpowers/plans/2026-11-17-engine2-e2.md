# Engine 2, milestone E2 (renderer core) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `bf2-render`, a wgpu renderer drawing an Engine 2 fight at 1080 x 1920 in HDR. It covers toon and
glass materials, many lights, a spotlight shadow map, tone mapping and readback, and a render job that writes a
correct 61 s mp4 of a TEST DUMMY fight.

**Architecture:** `bf2-render` owns the GPU: device, targets, pipelines, meshes and the frame. A frame is a plain
CPU-side `Scene`, made of a camera, lights and instances, that the renderer draws. The `Look2` trait (in
`bf2-render`) lets content turn a fighter's recorded step into instances. `bf-content/src/fighters2/test_dummy`
implements it. A `stage` module builds the arena, ring and balls. `bf-export` gains an Engine 2 job, and
`bf-engine` routes `render` there. The interpolation between 120 Hz steps lives in `bf2-render::fight_frame`.

**Tech Stack:** wgpu 30.0.1 (the workspace's version through eframe), WGSL, `pollster` for blocking on the
device in jobs and tests, `bytemuck`. The cloud runs on Mesa lavapipe (`apt-get install -y mesa-vulkan-drivers
libvulkan1`), and the PC runs on the RX 9070 XT.

**Spec:** `docs/superpowers/specs/2026-11-17-engine2-design.md` sections 3 and 8 (row E2).

## Global Constraints

- Output 1080 x 1920, 30 fps, 61.0 s (1,830 frames), h264 + aac, through `bf-export`'s existing ffmpeg discovery
  and `Encoder`. E2's audio is silence (E5 brings sound).
- HDR `Rgba16Float` colour, `Depth32Float`, MSAA 4x resolved before tone mapping. The final target is `Rgba8Unorm`
  (not sRGB; the shader encodes), read back with rows padded to 256 bytes.
- Coordinates: sim x and y are the floor, and sim z is height. In the renderer, Y is up, so a sim point (x, y, z)
  becomes render (x, z, −y). This lives in one function, `to_render(v: V3) -> [f32; 3]`, and is used everywhere.
- The default camera reproduces today's framing: target the ring centre, distance 27.5, pitch 58°, fov 36°
  (`bf-picture/src/ring/state.rs` `camera_keys`). E4 replaces it with the director.
- The art identity: low-poly instruments in glass balls, the ring, the arena, crowd and LED boards. The instrument
  meshes are the existing model JSON (`bf_picture::sprite::Mesh`, fan polygons with `rgb`, `emit`, `spec`).
- Windows only for the user. Cloud tests use lavapipe, and pictures are compared by property and tolerance, never
  by bytes across devices.
- Never edit `projects/`, `reelkit/`, `series/`. Nothing user-visible changes (TEST DUMMY stays hidden).
- Testing: only `bf2-render`, the `bf-content` `fighters2` tests, `bf-export`'s new job test and `bf-engine`.

## Rulings carried in

- **App preview moves to E6.** The spec puts "app preview" in E2's row, but nothing in the app can show an Engine
  2 fight until E6's matchup rules exist, and the dummy is hidden. E2 provides `Gpu::from_device(device, queue)`
  so E6 can share eframe's device. If that's wrong, it costs a small E6 task.
- **Bloom, flashes and every screen effect are E3.** E2's post is tone map plus exposure plus a neutral grade hook.

## Review Focus

1. **No GPU, or GPU lost.** Starting a render with no adapter must give a plain sentence ("This PC's graphics card
   could not be used for Engine 2: …"), not a panic. Pinned in Task 1 (`no_adapter_is_a_sentence` via an adapter
   filter that matches nothing).
2. **Row padding on readback.** 1080 × 4 = 4,320 is not a multiple of 256. The read-back image must have no
   sheared or garbage columns. Pinned in Task 2 (`readback_has_no_padding_garbage`, a gradient checked per pixel).
3. **Interpolating across hitstop and K.O.** Frames between steps during hitstop must not jitter, and frames after
   the last step hold it. Pinned in Task 6 (`frames_hold_during_hitstop`, `frames_past_the_end_hold_last_step`).
4. **Transparent glass sorting.** Two overlapping glass balls must draw back to front, whichever is nearer the
   camera. Pinned in Task 4 (`glass_sorts_back_to_front`).
5. **A cancelled render.** It must stop ffmpeg and leave no half file, the same as the current job's contract.
   Pinned in Task 7 (`cancel_leaves_no_file`).

### Task 3: Meshes and the scene description

**Files:** Create `studio/crates/bf2-render/src/mesh.rs`, `src/scene.rs`, `src/geom.rs`.

**Interfaces:**

  /*bit0 emit, bit1 two-sided*/, pub spec: f32 }` (Pod).
- Produces: `pub struct MeshData { pub verts: Vec<Vertex>, pub idx: Vec<u32> }`, built by `geom`: `icosphere(r,
  subdiv)`, `box_(size)`, `cylinder(r, h, n)`, `plane(w, d)`, `capsule(a: V3, b: V3, r, n)` (in render space), and
  `from_sprite_mesh(m: &bf_picture::sprite::Mesh, scale: f32) -> MeshData` (fan triangulation, flat normals from

- Produces: `pub struct MeshId(u32)` and `pub struct Meshes` with `fn add(&mut self, gpu, MeshData) -> MeshId`.
  Uploaded once.
- Produces: `pub enum Material { Toon { bands: u32 /*4*/, rim: [f32; 3], rim_power: f32 }, Glass { tint: [f32;
  3], opacity: f32 /*0.18*/, fresnel: f32 /*0.9*/ }, Emissive { strength: f32 }, Unlit }`.
- Produces: `pub struct Instance { pub mesh: MeshId, pub material: Material, pub model: [[f32; 4]; 4], pub colour:
  [f32; 4] /*multiplies vertex rgb; a = alpha*/ }`.
- Produces: `pub struct Light { pub pos: [f32; 3], pub colour: [f32; 3] /*HDR*/, pub range: f32 }`, plus `pub

- Produces: `pub struct Camera { pub eye: [f32; 3], pub target: [f32; 3], pub roll: f32, pub fov_deg: f32 }` and

- Produces: `pub struct Scene { pub camera: Camera, pub ambient: [f32; 3], pub spot: Option<Spot>, pub lights:

- Produces: `pub fn to_render(v: [f64; 3]) -> [f32; 3]` (the axis swap from Global Constraints).

### Task 4: Drawing: toon, glass, emissive, lights and the spot's shadow

**Files:** Create `studio/crates/bf2-render/src/renderer.rs`, `src/shaders/{shadow,lit,glass}.wgsl`.

**Interfaces:**
- Produces: `pub struct Renderer` with `Renderer::new(gpu: &Gpu) -> Renderer`, `pub meshes: Meshes`, and `pub fn
  render(&mut self, gpu: &Gpu, scene: &Scene, post: &Post) -> bf_picture::Rgb8`. The passes, in order:
  1. a shadow map from the spot (2048², depth only, opaque instances);
  2. an opaque pass (Toon, Emissive and Unlit with MSAA; forward lighting over the spot (shadowed, PCF 3x3) and
     up to 64 point lights in a uniform/storage buffer; toon quantises the diffuse into `bands`, adds rim light
     `rim × (1 − n·v)^rim_power`, and specular steps from vertex `spec`);
  3. a glass pass (transparent instances sorted back to front by view depth, fresnel plus specular, depth test on,
     depth write off);
  4. resolve, then tone map, then read back.
- Instances are drawn with per-instance data in a storage buffer, one draw call per mesh.

- [ ] **Step 1: Tests**, all on small scenes rendered at 270 x 480 through a `Renderer::render_sized`:
  - `toon_sphere_has_banded_shading` (a lit toon sphere: count distinct grey levels inside its silhouette's core,
    excluding the 2-pixel edge, ≤ bands + 2);
  - `point_light_tints_the_floor` (a red light over a white plane makes the floor under it redder than the
    corners);
  - `shadow_darkens_floor_under_ball` (a ball between the spot and the floor makes the floor under it darker than
    beside it);
  - `glass_is_see_through` (a red box behind a glass ball is still red through the ball's centre);
  - `glass_sorts_back_to_front` (two overlapping glass balls tinted differently: the nearer one's tint dominates
    the overlap, whatever order they're listed in);
  - `same_scene_same_pixels_on_one_device` (render twice and the bytes are equal).
- [ ] **Step 2: Run them to see them fail.**
- [ ] **Step 3: Implement.**
- [ ] **Step 4: Run them to see them pass.**

  - the arena floor (dark, wide plane);
  - the stands as tiers of boxes;

### Task 6: From the recording to frames

**Files:** Create `studio/crates/bf2-render/src/fight_frame.rs`. Modify `bf2-render/Cargo.toml` (dep `bf2-sim`).

**Interfaces:**
- Consumes: `bf2_sim::{Recording2, StepSnap, Ev}` (E1 Task 9).
- Produces: `pub struct FightFrame<'a> { pub rec: &'a Recording2, pub t_video: f64, pub t_fight: f64, pub step:
  usize, pub alpha: f64 /*0..1 toward step+1*/, pub snap: StepSnapLerp }`. `StepSnapLerp` holds the interpolated
  pos, facing, joints and projectile positions, plus the hp of `step`.
- Produces: `pub fn frame_at(rec: &Recording2, f: usize /*video frame*/) -> FightFrame`. It uses `t_video = f/30`
  and `t_fight = t_video − rec.t_fight`. Before the fight, it holds step 0. After the last step, it holds the last
  one. When either body has `hitstop > 0` at `step`, alpha is 0, so frames hold during hitstop. A projectile that
  doesn't exist at `step+1` isn't interpolated.
- Produces: `pub fn render_frame(r: &mut Renderer, gpu: &Gpu, stage: &Stage, looks: &[Box<dyn Look2>; 2], rec:
  &Recording2, f: usize, colours: [[f32; 3]; 2]) -> bf_picture::Rgb8`.

- [ ] **Step 1: Tests**, on a recording made by `bf2-sim` with a fixture fighter:
  - `frames_interpolate_between_steps` (a frame halfway between two steps gives the midpoint position);
  - `frames_hold_during_hitstop`;
  - `frames_before_the_fight_hold_step_0`;
  - `frames_past_the_end_hold_last_step`.
