# Engine 2, milestone E0 (plan and seams) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prepare the Studio for Engine 2 without changing anything Aedan sees. Fight files gain an engine
choice. Every fight goes through one gate that knows about engines. The four Engine 2 crates exist (empty for
now). Today's speeds get measured on the PC, and those numbers become E1's targets.

**Architecture:** `bf-core` gets an `Engine` enum and a `FightFile::engine` field, which is absent in every
existing file and means the current engine. A new crate, `bf-engine`, is the single place that turns a fight file
into a fight. For now it hands current-engine files to `bf_sim` exactly as today, and refuses Engine 2 files with
a plain sentence. E1 to E6 fill it in. `bf-content` learns which engines each fighter has. Right now every fighter
has only the current one. Four empty crates (`bf2-sim`, `bf2-render`, `bf2-fx`, `bf2-direct`) join the workspace.

**Tech Stack:** Rust 2024 (workspace `rust-version = "1.99.1"`), existing workspace crates, toml.

**Spec:** `docs/superpowers/specs/2026-11-17-engine2-design.md` (section 1 "Shape", section 6 "App integration",
section 8 row E0).

## Review Focus

1. **An existing fight file round-trips byte for byte.** A file with no `engine` key must write back exactly as it
   was read, and its search key must be unchanged, so seed shortlists cached on disk stay valid. Pinned in Task 1.
2. **Opening an Engine 2 file in today's app.** Search, balance, takes, render and the CLI must show a plain
   sentence, not a panic. Pinned in Task 2 (one test per entry point that has a test module in the cloud, plus a
   `bf-cli` test).
3. **A bad engine value.** `engine = 3`, `engine = "two"` or `engine = 1.5` gets refused with a one-line error that
   names `engine`. `engine = 1` written by hand is accepted, and is written back without the key. Pinned in Task 1.
4. **The search key separates engines.** The same fighters and settings on Engine 2 must not reuse a
   current-engine shortlist. Pinned in Task 1.
5. **A fighter's engines when the name is unknown or retired.** `engines("GUITAR")` and `engines("NOPE")` return
   an empty list and never panic. Pinned in Task 3.
