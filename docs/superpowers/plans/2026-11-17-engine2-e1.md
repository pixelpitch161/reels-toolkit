# Engine 2, milestone E1 (fight engine core) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `bf2-sim`, a deterministic fight engine. It has a ring floor plus height, balls with weapon rigs,
moves in phases with hitboxes on bones, freeze-on-hit, knockback, launches, juggles, grabs and slams, bounces,
clashes, guards, projectiles, seeded behaviour, a per-step recording and events v2. Two TEST DUMMY fighters must
fight reproducibly through `bf-engine`, and fight speed is measured against E0's numbers.

**Architecture:** `bf2-sim` is plain Rust on `bf-core`'s deterministic maths (`dmath`) and its RNG
(`rng::Generator`), with no other dependencies. Content (fighter definitions) is data built by Rust builder
functions, and the engine owns no fighter. The TEST DUMMY lives in `bf-content/src/fighters2/test_dummy/`.
`bf-engine` gains `fight()`, which dispatches on the file's engine.

**Tech Stack:** Rust 2024, `bf-core` (`dmath`, `rng`, `fightfile`, `grid`), `rayon` (speed example only).

**Spec:** `docs/superpowers/specs/2026-11-17-engine2-design.md` section 2 (fight engine), section 7 (test dummy),
section 8 row E1.

## Global Constraints

- Determinism: only `+ - * /`, `sqrt` (IEEE-exact), `abs`, `min`/`max` and `bf_core::dmath` for every other
  function (trig, `pow`, `exp`). Never `f64::sin` etc. Iterate `Vec`/arrays in index order, never hash maps. The
  same `Setup2` gives a bit-identical `Recording2` on every run and thread count.
- `#![forbid(unsafe_code)]`. No allocation inside the step loop when `record == false`, other than event `Vec`
  growth.
- Windows only. Never edit `projects/`, `reelkit/`, `series/`. Nothing user-visible changes: TEST DUMMY is not in
  `PORTED`, so `engines()` still returns `[]` for it and the app never offers it.
- Testing: only the tests of the crates this plan touches (`bf2-sim`, `bf-content` `fighters2`, `bf-engine`).
- Units are the current engine's: ring half-size `A = 3.0` inside the ropes, ball radius `R = 0.6`, `HP = 100`,
  seconds. Video timing comes from `bf_core::grid::Grid` (`t_fight`), and the fight stops at `t_max = 58.0`.

## Rulings carried in from E0

- **Sim rate is 120 Hz, not 240 Hz** (the spec lets the builder choose). The recording keeps every step, which
  supports 0.25x slow-mo at 30 fps exactly, and sub-frame motion blur interpolates between steps. Half the steps
  is what makes the speed target reachable.
- **Speed target:** E0's "fights/s at least today/4" contradicts the spec's "auto-balance about the same time as
  today" (and E0's own 1.25x line). The binding target is the full auto-balance in **at most 1.25x today's
  FLUTE vs TROMBONE time**, which means Engine 2 fights/s on all workers must be at least 0.8x today's. E0's
  measurements doc gets corrected in Task 10.

## Review Focus

1. **Determinism across thread counts and reruns.** The same seed gives a bit-identical recording on 1 worker and
   on all workers. Pinned in Task 9 (`same_seed_same_recording`) and Task 10 (the speed example compares outcomes
   of the 1-worker and N-worker passes).
2. **A ball tunnelling out of the ring.** A launch or a big knockback must never leave the ropes or sink under the
   floor, even at the highest speed a move can give. Pinned in Task 4 (`fast_ball_never_leaves_the_ring`).
3. **Stuck states.** A fight with both fighters in hitstun, held by a grab, or frozen in hitstop must always make
   progress. No infinite hitstop, and a grab always releases. Pinned in Task 5 (`hitstop_always_ends`,
   `grab_always_releases_even_if_holder_is_hit`).
4. **A fight that never ends.** No K.O. by `t_max` ends on HP (decision) or a draw, and never runs past `t_max`.
   Pinned in Task 9 (`no_ko_ends_at_t_max`).
5. **One hit landing many times.** A single active window hits a given target at most once unless the move says
   multi-hit. Pinned in Task 5 (`one_window_hits_once`).

### Task 2: Weapon rigs and poses

**Interfaces:**
- Produces: `pub struct Bone { pub name: &'static str, pub parent: Option<usize>, pub length: f64, pub radius: f64
  /*hitbox capsule radius*/ }`. Bones are in parent-first order, and that order is checked.
- Produces: `pub struct Rig { pub bones: Vec<Bone> }` with `pub fn bone(&self, name: &str) -> Option<usize>`.
- Produces: `#[derive(Clone, Copy, Default, PartialEq, Debug)] pub struct Joint { pub yaw: f64, pub pitch: f64,

- Produces: `pub fn solve(rig: &Rig, pose: &Pose, centre: V3, facing: f64, out: &mut Vec<Segment>)`, where

  its direction, at `centre + R·dir`, where `R` is passed in through `centre`'s caller. The signature is therefore
  `solve(rig, pose, centre, r_ball, facing, out)`. Each child starts at its parent's `b`. The direction is
  facing+yaw in the floor plane, tilted by pitch toward +z, using `dmath::sin/cos`.

### Task 4: Bodies and physics

**Files:** Create `studio/crates/bf2-sim/src/body.rs`, `src/physics.rs`.

**Interfaces:**
- Produces: `pub struct Body { pub pos: V3, pub vel: V3, pub facing: f64, pub r: f64, pub mass: f64, pub hp: f64,
  pub hitstun: u32, pub hitstop: u32, pub airborne: bool, pub juggle: u32, pub held_by: Option<usize>, pub
  mv: Option<MoveState>, pub cooldowns: Vec<u32>, pub meter: f64, pub low_done: bool }`. `z = 0` means on the floor
  (the ball's bottom touches the canvas when `pos.z == 0`).
- Produces: `pub fn integrate(b: &mut Body, rules: &Rules2, rng: &mut Generator, ev: &mut Events, who: usize,
  step: u32)`. It does nothing when `hitstop > 0` or `held_by.is_some()`. Otherwise it applies gravity when
  airborne, `pos += vel·dt`, then the floor (if `z < 0`, set `z = 0`. If `vel.z < -2.0` that's a `Land` event, or
  a `Bounce { what: Floor }` with `vel.z = -vel.z·floor_bounce`. Otherwise `vel.z = 0` and airborne is false),
  then floor friction on xy when grounded and not in hitstun, `vel_xy *= max(0, 1 − friction·dt)`. Then the ropes:
  for `|x| > a − r`, clamp, reflect `vel.x·rope_bounce`, and rotate xy velocity by a seeded `uniform(−give,
  +give)` degrees. Emit `Bounce { what: Rope }` if the speed is above 1.0. Same for y.
- Produces: `pub fn collide(a: &mut Body, b: &mut Body)`: sphere against sphere in 3D, a mass-weighted elastic
  push-apart with restitution 0.6, skipped when either is held.

- [ ] **Step 1: Tests:**
  - `launched_ball_lands`: vel.z 8 from the floor. It comes back to z 0 in under 1.5 s of steps and emits Land or
    Bounce.
  - `fast_ball_never_leaves_the_ring`: speed 60 in 8 directions for 600 steps. `|x|, |y| ≤ a − r` and `z ≥ 0` hold
    every step.
  - `hitstop_freezes`: pos is unchanged while hitstop > 0.
  - `rope_give_is_seeded`: the same seed gives the same bounced velocity, and a different seed differs.
  - `collide_separates`: overlapping balls end at least `r_a + r_b − 1e-9` apart, and momentum is conserved within
    1e-12.

### Task 5: Hits, guards, clashes, grabs and hitstop

**Files:** Create `studio/crates/bf2-sim/src/hits.rs`, `src/event.rs`.

**Interfaces:**
- Produces: in `event.rs`, `pub struct Events(pub Vec<Ev>)`, `pub struct Ev { pub step: u32, pub who: usize, pub
  kind: EvKind }` and
  `pub enum EvKind { MoveStart { mv: usize }, Windup { mv: usize }, Active { mv: usize }, Recovery { mv: usize },
  Contact { mv: usize, target: usize, point: V3, normal: V3, strength: f64, damage: f64, bones: Vec<usize> },
  Block { target: usize, point: V3 }, Clash { other: usize, point: V3 }, Launch { target: usize, up: f64 },
  Land, Bounce { what: Surface }, Slam { target: usize }, Grabbed { target: usize }, Released { target: usize },
  Spawn { proj: usize }, Expire { proj: usize }, ProjHit { proj: usize, target: usize, point: V3 }, Cue(Cue),
  Ability { mv: usize, first: bool }, LowHp, Ko { target: usize } }`, plus `pub enum Surface { Floor, Rope }`.
- Produces: `pub fn capsule_hits_sphere(s: &Segment, c: V3, r: f64) -> Option<V3 /*contact point*/>`.
- Produces: `pub fn resolve(world: &mut World, step: u32)`. `World` is defined in Task 8. Here it uses
  `world.bodies`, `world.segments[who]`, `world.defs`, `world.rules`, `world.events` and a per-body
  `hit_mask: Vec<bool>` (one window hits once). The order:
  1. Clashes first: both attackers in Active with overlapping active segments (segment against segment within the
     sum of radii). Both moves jump to Recovery, both get 6 steps of hitstop, and a Clash event fires at the
     midpoint.
  2. Then each attacker in index order: each live window's segments against the other body's sphere. On contact
     the damage is `hit.damage × dmg_scale × dmg_side[att] × guard × juggle_decay^juggle`, where `guard` is the
     target's current move's `guard`. A Block event fires instead of Contact when `guard < 1`.
  3. Hitstop for both is `min(hit.hitstop, max_hitstop)`.
  4. Knockback: velocity is `knock` along attacker→target in xy plus `lift` in z. `lift > 0` sets airborne, adds
     one to juggle and emits Launch.
  5. Hitstun on the target. The target's move is cancelled unless `armor`.
  6. Grab: sets `held_by` and emits Grabbed. While held, the target's position is the holder's grab bone tip. On
     release (after `hold` steps, or immediately if the holder takes a hit), the target gets downward `slam` and
     emits Slam when `slam > 0`, or a horizontal `throw` otherwise, and emits Released.
  7. HP at or below 0 emits Ko.
  8. Meter: the attacker gains `damage × 1.0` and the target gains `damage × 0.5`, capped at 100.

### Task 7: Behaviour (seeded move choice and movement)

**Files:** Create `studio/crates/bf2-sim/src/brain.rs`.

**Interfaces:**
- Produces: `pub struct Choice { pub mv: usize, pub range: (f64, f64) /*centre distance*/, pub weight: f64, pub
  cooldown: u32, pub needs_meter: bool, pub air: Option<bool> /*Some(true) only when airborne*/ }`.
- Produces: `pub struct Brain { pub choices: Vec<Choice>, pub speed: f64 /*move speed, 2.6 like today*/, pub
  think: u32 /*steps between decisions, 6*/, pub low: Option<usize> /*move fired once when HP < low_hp*/, pub
  orbit: f64 /*0..1, how much it circles instead of approaching*/ }`.
- Produces: `pub fn think(world: &mut World, who: usize, step: u32)`. It's free (no move, no hitstun, no hitstop,
  not held, and `step % think == who·3 % think`, so the two fighters think on different steps). It fires `low`
  first if due (emits `Ability { first: true }` and `LowHp`). Otherwise it collects the choices in range, off
  cooldown, with meter when needed and matching air state, then makes a weighted pick with `rng.random()`, or
  moves when none fits. Movement steers toward the opponent mixed with tangent by `orbit`, adds seeded heading
  jitter of ±10°, and sets the xy velocity's magnitude to `speed` when grounded. Facing always turns toward the
  opponent at up to 12 rad/s when free, and is locked during Active.
- Starting a move: emits `MoveStart` and `Windup`, consumes 100 meter if `needs_meter`, and sets the cooldown.
  Phase changes emit `Active` and `Recovery`. Cues emit `Cue` at their phase step. The first use of each Special
  emits `Ability { first }`.
