# Engine 2, milestone E5 (sound, music, HUD, captions, count-in and VS card) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give an Engine 2 fight its whole soundtrack and its on-screen text:
- the theme's bed, the fighters' parts and the full Composed system (Classic one click away), driven by the v2
  events and placed on E4's time map;
- music that **slows down with slow-mo by default**, with a fight-file switch to keep it at normal speed;
- shared v2 sound effects (light, heavy and special impacts, launches, landings, slams, a hitstop "freeze" swell);
- the story layer (lead changes, desperation move, final exchange, K.O. tape stop, victory solo) rebuilt from the
  v2 events;
- the HUD, the captions, the count-in and the VS card composited crisply over the 1080 x 1920 GPU frame;
- the render checks for Engine 2 and the seed search's story score in video time.

Then render the full TEST DUMMY video with sound for Aedan's review.

**Architecture:** one adapter, the **shadow recording**. `bf2-direct` turns a `Recording2` plus the `TimeMap`
into a current-engine `bf_core::recording::Recording`, with v1 event layouts (`hit`, `ability`, `rope`, `block`,
`clash`, `heal`), v2-only `v2.*` events, an `HP` array at 30 fps and `rules.{bpm,beat,t_fight}`. It's built on
one of two clocks: **video** (event times are `map.step_video_t(step)`) or **fight** (event times are
`t_fight + step·dt`). Everything downstream is reused unchanged on top of it: `Show::new` (captions),
`MusicCtx`, `StorySignal`, `score()`, `master()`, `bf_story::story_at` and `bf_story::score`.

The music slow-down is a **two-clock build spliced at the K.O.**:
- before the K.O., the score is built on the fight clock and resampled through the time map (varispeed, so pitch
  follows);
- from the K.O. on, the score is built on the video clock and isn't warped, so the stinger, the solo, the last
  bars and the loop seam stay on the video grid.

The UI is the existing CPU UI layer at 360 x 640, drawn twice (over black and over white) to recover a
premultiplied alpha matte. It's scaled up 3x nearest and alpha-composited on the GPU after tone mapping.

**Tech Stack:** `bf-sound` (score, mix, master, dsp), `bf-content` (soundtrack, composer, themes, `fighters2`),
`bf-core` (`Show`, `Recording`, `fightfile`), `bf-picture` (`ui`, `title`, `ring::hud`), `bf2-sim` (events v2),
`bf2-direct` (E4: `TimeMap`, `CameraTrack`, `project`), `bf2-render` (wgpu 30.0.1, WGSL), `bf-story`,
`bf-export` (checks, `job2`).

**Spec:** `docs/superpowers/specs/2026-11-17-engine2-design.md` section 3 "HUD, captions, count-in and VS card",
section 4 "Time map", section 5 "Sound and music", section 8 row E5, "Decided by Aedan" and "My calls" (music,
render checks, seed-search fit).

## Global Constraints

- Video spec unchanged: 61.0 s, 1080 x 1920, 30 fps (1,830 frames), h264 + aac, loop at the file boundary,
  safe zone, consistent loudness. The soundtrack is `bf_sound::NA` = 2,928,640 samples at 48 kHz.
- **Sound determinism:** the same `Recording2`, fight file and `DirectCfg` give sample-exact identical
  soundtracks on every run and thread count. Resampling uses a fixed-tap kernel in f64 with no FFT, in a fixed
  summation order. Noise seeds come from event steps, never from time floats in hash maps.
- **No flash cap** (Aedan, 2026-11-17 05:25Z): the flash check does not run on Engine 2 videos.
- Music slows with slow-mo by default, and the switch keeps it at normal speed (Aedan, 2026-11-17 05:25Z).
- The current engine's sound and picture must not change by one sample or byte. Every edit to a shared function
  (`score`, `personality`, `player`, `ring::hud`) is a pure addition or an extraction that leaves v1 identical.
- Windows only for the user. GPU tests run on lavapipe in the cloud and compare by tolerance.
- Never edit `projects/`, `reelkit/`, `series/`. TEST DUMMY stays hidden (not in `PORTED`, `available()` or
  `engines()`).
- Testing: only the tests of what changed (`bf2-direct shadow`, `bf-sound warp`/`v2`/`score`, `bf-content
  soundtrack2`/`fighters2`/`personality`, `bf-core fightfile`, `bf-picture ring::hud`, `bf2-render overlay`/`ui2`,
  `bf-engine`, `bf-export checks::engine2`/`job2`). Never the full suite.

## Rulings carried in

- **Interfaces assumed from E4** (being built in parallel; the names follow its plan):
  - `bf2_direct::TimeMap` with `from_recording(rec: &Recording2, cfg: &DirectCfg) -> TimeMap` and `build(events,
    steps, dt, t_fight, ko, cfg)`;
  - `fn fight_t(&self, t_video: f64) -> f64`, which is fight seconds **from the fight start**;
  - `fn video_t(&self, t_fight: f64) -> f64` and `fn step_video_t(&self, step: u32) -> f64`, which are absolute
    video seconds;
  - `fn rate(&self, t_video: f64) -> f64`, which is fight-seconds per video-second and is 0 only in the K.O.
    freeze;
  - `fn ko_video_t(&self) -> Option<f64>` and `fn extra(&self) -> f64`.

  Also assumed: `bf2_direct::{CameraTrack, CamPose, project, to_render}` and `bf_engine::ko_video_t`. Hitstop
  is inside the fight (fight time runs while bodies freeze), so music never stops for hitstop. If E4 lands with
  other names, map them in Task 1 and note it there.
- **Sound for Engine 2 is driven through the existing score, via an adapter**, not a new score. The shadow
  recording feeds the unchanged bf-sound/bf-content pipeline, so every bed, the Composed arrangement, Classic,
  `StorySignal`, captions and the beat sheet carry over for free. v2 detail that v1 has no slot for rides as
  **trailing fields** on `hit` (v1 readers index at most element 8) and as new `v2.*` event kinds that v1 code
  never matches.
- **The slow-mo stretch is a varispeed resample of the whole pre-K.O. mix** through the music clock `m(v)`:
  - `m(v) = v` for `v < t_fight`;
  - `m(v) = t_fight + map.fight_t(v)` up to the K.O. (the music clock is the fight clock);
  - from the K.O. on, the video-clock build is used unchanged.

  Pitch follows the speed, like tape. Sound effects in that stretch slow and pitch down with the music (the
  spec leaves this per sound to the builder). Rates are at most 1, so it's pure interpolation with no
  anti-alias filter: a 16-tap Lanczos (a = 8) windowed sinc. A fractional position within 1e-9 of an integer
  copies the sample exactly, so an identity map is bit-exact.

  The seam is a 5 ms linear crossfade ending exactly at the K.O. sample, so the K.O. hit's attack is untouched.
  The fight-clock build is skipped when the two clocks agree at the K.O. (`|t_ko_fight − ko_video| ≤ 0.5/SR`).
- **The switch is `music.slowmo` in the fight file:** `"follow"` (the default, never written) or `"steady"`.
  `steady` builds only the video-clock score and warps nothing.
- **The hitstop "freeze"** is a `v2.freeze` event at each contact whose hitstop is at least 4 steps (1/30 s). It
  carries a band-passed noise swell plus a held sine at the impact's pitch, lasting the hitstop, scaled by
  strength.
- **UI compositing:** the CPU UI layer stays the one source of the look:
  - `bf-picture`'s `countdown`, `fight_hud`, `draw_captions` and `TitleCard::draw_logged` draw at 360 x 640,
    once over black (`B`) and once over white (`Wt`);
  - per pixel, `α = 1 − mean_c(Wt_c − B_c)/255` clamped to [0, 1], with premultiplied colour `B`;
  - a frame where the card is shut (`door_offset == 0`) is taken as fully opaque over black, because the
    card's slam glow is additive and saturates over white, while the frame behind it shows at most 3 %;
  - the matte is uploaded as a 360 x 640 `Rgba8Unorm` texture, upscaled exactly 3x with nearest sampling (the
    pixel font stays crisp, the same pixels as today's videos), and blended `One, OneMinusSrcAlpha` into the LDR
    target **after tone mapping** (the UI's bytes are final sRGB values, and they must not bloom).

  The draw log stays in 360-space, so the existing `safezone()` check runs unchanged.
- **Engine 2 search story:** `bf_engine::candidate2(ff, seed, sheet)` fights with `record = false`, builds the
  `TimeMap` from the events and a video-clock shadow (events only, no `HP` array), then calls
  `bf_story::story_at(&shadow, grid.t_fight, sheet, low_names)` and `bf_story::score`. So every beat-sheet window
  (the K.O. 49 to 53 s, the caption targets, the max gap) is in video time. The balance band (49 to 52 s) is
  E6's, and it uses `bf_engine::ko_video_t`.
- **Checks on Engine 2:**
  - unchanged: safe zone, levels, loudness, loop picture and loop audio;
  - **K.O. window** is `ko_video_t` in [49, 53];
  - **band** is the existing `band()` given the video-clock `Show`, so its sections (FIGHT! to 10 s, ... 44 s to
    the K.O.) are video seconds;
  - **focus** gets an Engine 2 definition: from FIGHT! to the K.O. + 2.5 s, each ball's projected circle is
    inside the 1080 x 1920 frame on every frame, and its centre is inside the safe zone `(60, 288, 1020, 1500)`
    on at least 98 % of frames (E4's framing rule);
  - flash is off.
- **TEST DUMMY's sound identity:**
  - a hidden roster entry, compiled from `fighters2/test_dummy/roster.json`, whose `pp` is MARIMBA's voice and
    whose abilities name its own moves;
  - MARIMBA's voice and personality, borrowed, so the Composed system writes it a line;
  - its own part, `fighters2/test_dummy/sound.rs`;
  - a small metronome model for the VS card close-up.

## Review Focus

1. **A click or a gap at the K.O. seam,** above all when the K.O. lands inside or just after a slow-mo. The
   largest sample-to-sample step within ±2 ms of the seam must be no larger than 1.5x the largest step in the
   50 ms before it. Pinned in Task 3 (`splice_has_no_click`) and Task 6 (`ko_after_slowmo_is_clean`).
2. **No slow-mo, or `steady`.** The soundtrack must equal a single video-clock build sample for sample, and a v1
   fight's soundtrack must not change at all. Pinned in Task 3 (`identity_warp_is_bit_exact`), Task 4
   (`v2_hook_is_silent_on_v1`) and Task 6 (`steady_is_one_build`).
3. **UI drawn with a non-linear op.** A HUD, caption or card draw that saturates or reads the background would
   show as halos after matting. Over 5 random backgrounds at every 0.25 s frame of the dummy video, compositing
   the matte must equal drawing directly within ±2 per channel. Pinned in Task 7
   (`matte_matches_direct_draw`).
4. **A fight with no K.O.** (decision or draw). The soundtrack and the UI refuse with a plain sentence (the
   `Show`'s `NoKo`), and the search marks it a misfit, with no panic. Pinned in Task 6
   (`no_ko_is_a_sentence`) and Task 9 (`candidate2_without_ko_does_not_fit`).
5. **Determinism under threads.** Two `build_soundtrack2` calls on 1 and 8 rayon threads give identical master
   bits. Pinned in Task 6 (`soundtrack2_is_deterministic`).

### Task 1: The shadow recording

**Files:** Create `studio/crates/bf2-direct/src/shadow.rs`. Modify `bf2-direct/src/lib.rs` (`pub mod shadow`).
`bf2-direct` already depends on `bf-core` and `bf2-sim` (E4).

**Interfaces:**
- Consumes: `TimeMap` (E4), `bf2_sim::{Recording2, Ev, EvKind, FighterDef, Tag}`, `bf_core::recording::Recording`,
  `bf_core::event::{Event, Value}`, `bf_core::grid::Grid`.
- Produces: `#[derive(Clone, Copy, Debug, PartialEq, Eq)] pub enum Clock { Video, Fight }`.
- Produces: `pub fn shadow(rec: &Recording2, defs: [&FighterDef; 2], map: &TimeMap, clock: Clock, grid: &Grid) ->
  Recording`. It fills:
  - `names`, `seed`, `winner = outcome.winner`, `fps = 30`, `f0 = round_half_even(grid.t_fight·30)`, and
    `rules` with `bpm`, `beat` and `t_fight` from `grid`;
  - `t_ko`: `map.ko_video_t()` on Video, and `outcome.t_ko` on Fight;
  - `HP`: an `F64` array of shape `[n, 2]`, with one frame per 1/30 s from the fight start to the K.O. clock
    time + 1 s. Frame `i` reads `steps[s].hp`, where `s` is the step at that clock time (on Video, through
    `map.fight_t`), clamped to the last step. It's left out when `steps` is empty (search).
  - `events`, each at its clock time rounded with `py::round_nd(t, 5)` and in step order:
    - `Contact{mv, target, point, strength, damage}` becomes `hit` `[who, target, damage, x, y, move_name, 0,
      strength, tag, hitstop_s]`. `tag` is `"special"`, `"heavy"` or `"light"`, from the move's tags. `hitstop_s`
      is the move's largest `HitDef.hitstop`, capped at `rules.max_hitstop`, times `dt`. When `hitstop_s ≥
      4·dt`, a `v2.freeze` `[who, target, strength, hitstop_s, x]` follows it.
    - `ProjHit{proj, target, point}` becomes `hit` with `move_name` = the spawning move's name, taking
      strength and damage from the next `Contact` of the same step, if there is one. Otherwise strength is 0.3.
    - `Block{target, point}` becomes `block` `[target, who, x, y, "guard"]`.
    - `Clash{point}` becomes `clash` `[-1, x, y]`.
    - `Bounce{Rope}` becomes `rope` `[who, ax, side, px, py, speed]`, where `ax`/`side` are the nearest rope and
      `speed` is the ball's planar speed at that step. On Fight clock with no steps, speed is 2.6.
    - `Ability{mv, first}` becomes `ability` `[who, move_name, kind, first as Int]`, where `kind` is `"low"` for
      a `Tag::Low` move and `"special"` otherwise.
    - `Launch{target, up}` becomes `v2.launch` `[who, target, up]`.
    - `Land` becomes `v2.land` `[who, x]`.
    - `Slam{target}` becomes `v2.slam` `[who, target, x]`.
    - `Windup{mv}` on a Heavy or Special move becomes `v2.windup` `[who, move_name, tag, windup_s]`.
    - `Ko{target}` becomes `v2.ko` `[who, target]`.
    - Everything else is dropped.
- Produces: `pub fn low_name(def: &FighterDef) -> &str` (the first `Tag::Low` move's name, or `""`).

### Task 3: The varispeed warp and the K.O. splice

**Files:** Create `studio/crates/bf-sound/src/warp.rs`. Modify `bf-sound/src/lib.rs` (`pub mod warp`).

**Interfaces:**
- Produces: `pub const LANCZOS_A: usize = 8;` and `pub const SEAM_FADE: usize = 240;` (5 ms).
- Produces: `pub fn warp(x: &[[f64; 2]], src: &dyn Fn(usize) -> f64, n: usize) -> Vec<[f64; 2]>`. Output sample
  `i < n` is `x` read at source position `src(i)` (in samples) with the Lanczos kernel. Taps outside `x` read 0,
  and the kernel weights are normalised by their sum. `src` must be non-decreasing, and a decreasing step
  panics in debug.
- Produces: `pub fn warp_mix(m: &Mix, src: &dyn Fn(usize) -> f64, n: usize) -> Mix` (each bus, in
  `bus_names()` order).
- Produces: `pub fn splice(pre: &Mix, post: &Mix, seam: usize) -> Mix`. The bus set is the union, in `post`'s
  order and then `pre`'s new ones. A bus missing on one side is zeros. The result has `post`'s length. Samples
  before `seam − SEAM_FADE` are `pre`'s, from `seam` on they're `post`'s, and in between there's a linear
  crossfade.
- Produces: `pub fn music_src(t_fight: f64, fight_t: &dyn Fn(f64) -> f64) -> impl Fn(usize) -> f64` (`m(v)·SR` per
  the ruling, `v = i/SR`).

- [ ] **Step 1: Tests:**
  - `identity_warp_is_bit_exact` (`src(i) = i`, so the output equals the input bit for bit);
  - `half_speed_halves_pitch` (a 1 kHz sine warped at rate 0.5 measures 500 Hz ± 2 Hz by zero crossings);
  - `warp_is_deterministic` (twice gives the same bits);
  - `splice_takes_each_side` (well away from the seam, the samples equal `pre` and `post` exactly);
  - `splice_has_no_click` (two unrelated sines: the largest step within ±2 ms of the seam is ≤ 1.5x the largest
    in the 50 ms before it);
  - `splice_unions_buses`.

### Task 4: Shared v2 sound effects in the score

**Files:** Create `studio/crates/bf-sound/src/music/v2.rs`. Modify `bf-sound/src/music/mod.rs` (`pub mod v2`) and
`bf-sound/src/score.rs` (one call, `v2::shared_events2(ctx, bed, &mut mix)?;`, right after `shared_events`).

**Interfaces:**
- Produces: `pub fn impact(strength: f64, tag: &str, seed: u64) -> Vec<f64>` (mono, peak ≤ 1):
  - light (strength under 0.4): `synth::thud(0.12, 180.0, 90.0, seed)` plus a 20 ms band-passed 2 to 6 kHz
    click;
  - heavy (0.4 to 0.85): `thud(0.30, 120.0, 45.0)` plus a 60 ms band-passed 0.8 to 4 kHz crack;
  - special (above 0.85, or tag `"special"`): heavy plus a `thud(0.9, 70.0, 30.0)` sub and a 0.4 s noise tail
    at 300 to 2,000 Hz.

  The gain grows with strength.
- Produces: `pub fn freeze_swell(strength: f64, dur: f64, seed: u64) -> Vec<f64>` (a noise swell rising over
  `dur` and then a 0.15 s release, plus a held sine at `90 + 140·strength` Hz).
- Produces: `pub fn shared_events2(ctx: &MusicCtx, bed: &dyn Bed, mix: &mut Mix) -> Result<(), MusicError>`. Up to
  `show.t_ko + 0.01`, on bus `"fx"`, with pan `clip(x/3.5, −0.6, 0.6)`:
  - `hit` with at least 10 fields gets `impact(e[9], e[10], step-seed)` at `e.t`, gain 0.10;
  - `v2.freeze` gets `freeze_swell`, gain 0.05;
  - `v2.launch` gets a `synth::whoosh(0.35, 300.0, 3000.0, WHOOSH_RISE, seed)`, gain 0.06;
  - `v2.land` gets `thud(0.18, 110.0, 60.0)`, gain 0.05;
  - `v2.slam` gets `impact(1.0, "special")` plus `bed.landing()`'s first gain, at the slam;
  - `v2.windup` on a special gets a reverse swell `whoosh` of length `windup_s`, ending on the active step,
    gain 0.05.

  The seed is `noise_seed(H, t·1000)`.

  It never asks for a note, so the note cache and the noise stream are untouched, and it never matches a v1
  kind.

`bf-content/Cargo.toml` (dep `bf2-direct`; check that `bf2-direct` does not depend on `bf-content`).

**Interfaces:**
- Consumes: `shadow`, `Clock` and `low_name` (Task 1), `SlowmoMusic` (Task 2), `warp_mix`, `splice` and
  `music_src` (Task 3), `SoundBuild` and `validate` (existing), and `TimeMap` (E4).
- Produces: `pub struct Sound2 { pub soundtrack: Soundtrack, pub show: Show /*video clock*/, pub shadow:
  Recording /*video clock*/, pub levels: Levels, pub builds: u8 /*1 or 2*/ }`.
- Produces: `pub fn build_soundtrack2(rec: &Recording2, defs: [&FighterDef; 2], map: &TimeMap, ff: &FightFile) ->
  Result<Sound2, ContentError>`:
  1. Run `validate(ff)`.
  2. Make `sv = shadow(.., Video, ..)` and `show_v = Show::new(&sv, ff)?`.
  3. Build `V = SoundBuild::new(&show_v, &sv, ff)?.score()?`.
  4. If `ff.music.slowmo == Follow` and the clocks differ at the K.O. (the ruling), make `sf = shadow(..,
     Fight, ..)`, `show_f` and `M`. Then `mix = splice(&warp_mix(&M, &music_src(..), seam), &V, seam)`, with
     `seam = round_half_even(ko_video·SR)`.
  5. Master with V's build's `master()`.

  The whole thing runs inside `catch_unwind`, as `build_soundtrack` does.

**Interfaces:**
- Produces: `pub struct Overlay { pub w: u32 /*360*/, pub h: u32 /*640*/, pub rgba: Vec<[u8; 4]> /*premultiplied*/

  texture, and every later render draws a full-screen triangle over the LDR target with `textureLoad` at `pixel /
  3`, blend `One, OneMinusSrcAlpha`, once per output frame even with sub-frame accumulation. `None` clears it.
