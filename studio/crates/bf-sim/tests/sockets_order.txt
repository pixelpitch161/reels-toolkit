# The engine's sockets in the order `fight.py` reaches them (the kit's commit of this milestone), for
# `tests/sockets.rs`. Transcribed from `projects/ballfight/fight.py`: each line is a socket's name as the engine logs
# it with `Fight::trace_sockets` on, the `fight.py` line(s) it stands for, and when it is reached:
#
#   setup    once, in `run()` before the loop (`Schedule::new`)
#   frame    at every recorded frame (`snap`, `Frames::snap`)
#   step     on every step
#   beat     on a step that reaches a beat
#   unlock   on a beat, for an unlock whose turn it is (`abilities_step`'s loop over the two unlocks)
#   ability  when an ability fires (`trigger`)
#   hit      when `damage` is called
#   knock    when `knock` is called
#   clash    when the balls overlap and may clash
#   lance    on a step of a thrust in progress (`thrust_step` past its idle branch)
#   ringhit  when a ring's front passes the enemy (`effects_step`, the wave branch)
#   slamhit  when a slam lands on the enemy (`effects_step`, the slam branch)
#   copy     when IDENTITY CRISIS fires a copied ability (`trigger(..., quiet=True)`)
#
# Lines that run once per fighter appear twice, fighter 0's first. Existing calls (striker, blade, effects,
# abilities) are listed among the sockets, so the order of the new ones against them is checked too. The kinds
# older than the kit's (volley, pulse, pack, rattle, ...) have no socket: they stay `SLOT` comments in the code.
#
# name                     fight.py      when
